# ☕ 카페쿠피 IT 인프라 혁신 및 프로세스 최적화

## 📌 프로젝트 개요
![카페쿠피_v0 2_9](https://github.com/user-attachments/assets/2f7e4609-3dd0-4fb3-8ec3-18fe2fe80d20)

- **프로젝트 명**: 카페쿠피 IT 인프라 혁신 및 프로세스 최적화
- **대상 기업**: ㈜경희매니지먼트컴퍼니 (Kyung Hee Management Company) - 식품유통사업부 카페쿠피  
- **기업 특성**: 경희대학교의 자회사형 장애인표준사업장

본 프로젝트는 고객, 직원, 관리자 등 다양한 이해관계자의 IT 인프라를 통합하고, 전반적인 주문·재고·관리 프로세스를 최적화하여 **하나의 플랫폼에서 통합 운영**될 수 있는 환경을 구축하는 것을 목표로 한다.

---

## 🎯 프로젝트 목적 및 방향

- **목표**: 주문 및 재고관리, 고객 응대, 내부 운영 등 다양한 업무를 하나의 플랫폼으로 통합하여 관리 효율성과 사용자 경험을 극대화
- **개발 방식**: Agile 방법론 기반. 기업의 요구사항을 지속 반영하며 유연하게 개발

---

## 🔍 개선 대상 영역
![카페쿠피_v0 2_11](https://github.com/user-attachments/assets/bd6445ab-0cd1-4885-8455-290ad1c62b46)
- **1차 개선 포인트**: 주문 및 재고 관리 시스템의 자동화 및 최적화
- **기존 시스템의 한계**: 수기 입력, 시스템 연동 불가, 재고 현황 실시간 반영 어려움
- **개선 방향**:
  - Web/App 기반의 통합 시스템 개발
  - 데이터 자동화 및 실시간 처리
  - 권한 기반 사용자 관리 (직원, 관리자, 고객 등)

---

## 🛠️ 기술 스택

### 🔹 Frontend
- **Web**: React, JavaScript
- **App**: React Native, TypeScript

### 🔹 Backend
- **API 서버**: Django, Python
- **DBMS**: MySQL
- **비동기 처리**: Celery + Redis

### 🔹 DevOps & Infra
- **CI/CD**: GitHub Actions
- **Container**: Podman (Docker 대체)
- **Reverse Proxy**: Nginx
- **스케줄링/비동기**: Celery + Redis
- **서버**: AWS EC2 (`t2.micro` → 추후 `t4g.medium` 업그레이드 예정)
- **DNS**: AWS Route53

## 🧱 시스템 아키텍처
![카페쿠피_v0 2_38](https://github.com/user-attachments/assets/34ad935c-5ba8-4bfa-9336-2af0f017b638)
### 📁 Application Layer
- **사용자 접근성 최적화**: 프론트와 백을 명확히 분리하여 반응성과 보안성을 확보
- **역할별 기능 제공**:
  - **고객**: 주문, 알림, 피드백
  - **직원**: 재고 조회, 주문 접수, 매장 운영
  - **관리자**: 전체 데이터 통계 및 관리 기능

### 🌐 Infrastructure Layer
- GitHub Action으로 자동 배포 파이프라인 구축
- Podman으로 구성된 Nginx, Django, Redis 컨테이너들을 pod 단위로 운영
- 개발 서버와 배포 서버 모두 동일 구조 유지
